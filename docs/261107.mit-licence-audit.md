## What changing a licence requires
A copyright holder can offer their own work under another licence. Previously issued GPL permissions continue for previous releases. Third-party GPL adaptations need permission from the relevant holders or replacement with independently implemented/permissively sourced code; small edits, renamed variables, a C-to-C++ translation or a new API do not establish independent authorship. See the [GNU licensing FAQ](https://www.gnu.org/licenses/gpl-faq.en.html) and [GPLv3 section 5](https://www.gnu.org/licenses/gpl-3.0.html#section5).

The US Copyright Office distinguishes protected program expression from functional algorithms in [Circular 61](https://www.copyright.gov/circs/circ61.pdf). That distinction supports implementing the same mathematical method independently; it does not by itself clear a particular port or settle jurisdiction-specific borderline cases. Record the mathematical specification, new implementation provenance and validation rather than promising a legal clean room after already inspecting the source.

A project may offer its own code under MIT while retaining compatible third-party BSD/Apache/CC0 components under their original terms. That differs from declaring every file exclusively MIT. The [MIT licence](https://opensource.org/license/mit) itself requires retention of copyright and permission notices. Apache/BSD obligations also remain; a bibliography alone is insufficient.

## Your phylogenetic algorithms and earlier replacements
The user-controlled tree, LCA, reconciliation, dSPR, likelihood, ASR/PCM and data/model contributions do not need rewriting merely because an earlier release used GPL. Their original mathematical references can remain as scientific attribution. This is conditional on the underlying code genuinely being within the confirmed rights, rather than inherited third-party portions.

Existing documentation describes current hashtable, suffix-array, dense SVD, simplex and assignment implementations as replacements for older implementations. Those comments are useful leads, not proof of independence. Current hashtable source uses a small open-addressed implementation; the simplex source expressly records replacing an incomplete GSL draft. Review actual derivation/history before marking these cleared. Historical references to Rec-I-DCM3, GOPTICS, SVDLIBC or the Hungarian library do not by themselves prove those implementations are still present, nor establish that a rewrite necessarily eliminated every borrowed element.

## Recommended implementation sequence
1. Record the ownership confirmation and keep the present GPL release intact while preparing replacements. Pin exact upstream source revisions and grants for every retained third-party component.
2. Re-source permissive hash/RNG originals, independently replace unresolved small helpers, and remove unnecessary historical source copies. Keep the historical bibliography and add a separate current third-party notices/provenance manifest.
3. Replace the GSL/qrng combinatorics and quasi-random code from documented mathematical specifications. Preserve behaviour where needed; document changed sequences otherwise.
4. Replace the R-derived probability kernels. Preserve robust log tails, quantiles and convergence/error behaviour; compare against high-precision numerical oracles and existing regressions. This deserves more care than changing comments.
5. Review the remaining modules, headers, tests, generated distribution and notices. Only then update LICENSE, per-file SPDX/copyright statements, README/docs/package metadata and release notes together. Run the full numerical/package/header/downstream checks.

For historical entries, use wording such as “Earlier releases incorporated implementation X under GPL; the current implementation was independently written from specification Y” only after that statement is true and supported by recorded work. Retained third-party code still needs its real attribution/licence. No historical reference needs to be deleted simply because the new version becomes permissively licensed.
## Scope and limitations
This pass inspected the tracked source/build/reference material and targeted source comments/history; it did not perform an exhaustive similarity comparison against every upstream revision, verify all possible ownership assignments or provide a patent analysis. Some upstream file fetches failed and remain explicitly unresolved. There is currently no complete third-party licence manifest. The bibliography alone cannot establish that every current line is solely user-owned or permissively licensed.
