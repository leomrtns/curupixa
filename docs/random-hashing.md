# Random generators and hashes
Include `curupixa/global/random_number.h` for worker streams, or `curupixa/global/global_variable.h` for context-based draws. These functions belong to `curupixa_phylogenetics`; the higher libraries use the same implementation. Sampling accepts explicit random state and does not start threads.
## Random streams
The default context generator and `crpx_rng_stream` now use Blackman and Vigna's xoshiro256++ 1.0. SplitMix64 expands the seed into four 64-bit words. Worker streams occupy 32 bytes, require no allocation or lock, and reproduce the same sequence for the same seed, stream identifier and calls. Seed zero is a reproducible worker-stream seed; the context constructor retains its convention that zero requests operating-system entropy. Context draws are locked when several threads share a context; the assignment of those draws to threads depends on scheduling.
The stream structure has grown, so rebuild downstream applications. Existing drawing functions retain their parameters, but sequences have changed. The context's explicit generator selectors retain IDs 0..18 and 20; ID 19, the GPL-derived Xorgens implementation, is retired and returns `CRPX_ERROR_INVALID_ARGUMENT` from the checked selector. The default is now ID 17. The low-level Abyssinian generator and its seeding helper have also been removed because their permissive provenance was unresolved. No retired name or identifier silently selects another algorithm.
Different stream identifiers give different starting states for a fixed seed, without guaranteeing disjoint sequences. For disjoint blocks, initialise one stream, copy it for a worker, then jump the original before making each further copy:
```c
crpx_rng_stream next_worker;
crpx_rng_stream_init (&next_worker, seed, 0);
for (size_t i = 0; i < worker_count; i++) {
  workers[i].random = next_worker;
  crpx_rng_stream_jump (&next_worker);
}
```
Each jump advances by $2^{128}$ draws. Each worker must consume fewer than that many raw draws; distribution samplers can consume several draws per result. Jumping does not allocate or draw entropy. The historical `crpx_xoroshiro_pp_seed256` and `crpx_xoroshiro_star_seed256` names refer to `xoshiro256++` and `xoshiro256**` respectively; their names predate this distinction in Curupixa.
Bounded integers now use multiply-high reduction with rejection, following [Lemire (2019)](https://doi.org/10.1145/3230636). Both context and worker APIs call the same reduction helper. The 32-bit context draw now takes the high 32 bits directly. These are generators for simulation and numerical algorithms; use an operating-system cryptographic generator for secrets.
## Byte hashes and integer mixers
The public declarations remain in `curupixa/global/hash_functions_generators.h`. Integer mixers are implemented in `hash_functions_generators.c`, ordinary byte hashes in `hash_bytes.c`, and MetroHash in `hash_metro.c`. The private byte-reading helpers accept unaligned keys and define little-endian key words. Seeds are native integers at the supplied addresses; they may also be unaligned. For 128-bit hashes, the optional output contains two native `uint64_t` words. Serialise those words explicitly if a persistent file format needs a fixed byte order.
FastHash, the MetroHash variants and SuperFastHash have been replaced from verified permissive sources rather than their previous GPL intermediary. FNV-1 is implemented from its multiply-then-XOR definition. The historical Mailund-named functions now call the original public-domain Jenkins one-at-a-time and lookup2 algorithms. The unused rotating hash has been removed; no verified permissive source was established for that adaptation.
Several corrections change outputs. FastHash now reads `length / 8` complete words rather than `length * 8`. Fletcher treats its argument as a byte count, sums little-endian 16-bit words modulo 65535 and zero-pads an odd final byte. Jenkins lookup2 uses the correct word offsets and total length. Pearson handles an empty key and shifts 64-bit lanes without integer-promotion errors. The two multiplication mixers now fold the full 128-bit product by addition or XOR; this also changes the convenience 64-bit returns from the 128-bit hashes. The underlying MurmurHash, MetroHash and SipHash 128-bit output words retain their specified values on little-endian hosts. Rebuild stored hashes produced by affected functions.
For ordinary table keys, FastHash or MurmurHash3 are available without adding a dependency. SipHash-2-4 accepts a 128-bit key when a keyed hash is required. FNV is retained for compatibility. Checksums, integer permutations and statistical RNGs serve different purposes; the old comments about passing randomness tests should not be interpreted as collision-resistance claims.

## Validation
The dependency-free `test_rng_hash` suite uses upstream hash and jump fixtures, exact-size allocations over input lengths 0..257 and alignment offsets 0..7, checksum identities and bounded-draw checks. Runtime tests exercise every retained context selector and concurrent drawing. Static, shared and sanitizer builds exercise the same tests.
A separate local comparison compiled the original sources and checked 31,440 hash results across lengths, seeds and alignments, plus 30,000 xoshiro, jumped-xoshiro and Mersenne Twister outputs. These comparisons establish agreement with those algorithms; they are not a new statistical certification of any RNG family.

Repeated local shared-library runs of ten million draws per case put worker-stream draws around 2.5–3.0 ns and direct xoshiro kernel calls around 2.2–2.6 ns, compared with 2.5–4.2 ns for direct SplitMix calls. Context timings varied substantially (roughly 9–27 ns), and neither the former default nor its replacement was consistently faster. These measurements support no blanket context-speedup claim.
