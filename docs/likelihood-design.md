# Likelihood implementation and backend direction
The current implementation uses the mathematical models in biomcmc-recomb and guenomu with new ownership, arbitrary-state data and recoverable errors. The [reference audit](likelihood-reference-audit.md) identifies the original formulas and assumptions; the [developer guide](character-analysis.md) gives the public calling interface and a complete binary example.
## Models and statistical assumptions
Poisson/equal-rates and F81 support arbitrary positive state counts; HKY supports DNA in A,C,G,T order. The stationary mean substitution rate is one, except for the constant one-state process. Frequency weights must be positive and finite. Constructors normalise them with checked arithmetic. Fixed transition matrices use analytic exponential decays; the sitewise exponential-prior mode replaces each decay by its analytic Laplace transform. No numerical eigensystem is used.
The exponential parameter is a mean length in expected substitutions per site. Integration is independent per supplied edge and per site. Integer pattern weights remain exact repetitions of that sitewise model. An alignment-wide integral with one length per edge shared by all sites defines a different statistical model and is not implemented by averaging transition matrices.
Fixed mode uses each edge's own tree length or an explicit per-node override. Sitewise mode accepts distinct edge means or a common mean without adding branch lengths to the tree. The stem above the root is ignored. An explicit binary-root collapse parameter chooses one process for the edge divided by an artificial root; otherwise both supplied child edges retain their own processes. Other degree-two vertices remain explicit. No topology is modified during scoring.
## Workspaces and partials
Character data and substitution models are immutable and separately owned. A numerical workspace borrows no tree, data or model after returning. Re-evaluating validates the leaf-name mapping and rebuilds analytic edge kernels, traversal and downward partials. This conservative full refresh prevents stale model/length/topology caches. Independent workers can share read-only inputs while retaining separate workspaces; MPI communication and work partitioning belong to the application.
Likelihood calculation uses log-space conditional vectors. Every child is incorporated with log-sum-exp; per-node normalisation and scales bound the stored vectors. Impossible data return negative infinity with a successful status. Zero-weight patterns contribute nothing. Scalar outputs remain unchanged on error, and failed calls invalidate cached views. Getters expose per-pattern logs, normalised downward log partials and corresponding scales. Ordinary partials use a separate exponentiated scratch vector whose tiny components can underflow; the log accessor preserves those contributions.
Retaining all partials uses $O(PVS)$ doubles for patterns $P$, nodes $V$ and states $S$. Streaming reuses $O(VS)$ working storage, retains $O(P)$ pattern logs and disables node-partial getters. Input pattern storage separately uses $O(PNS)$ doubles for taxa $N$. The current data representation prioritises an explicit common interface; sparse-tip encodings can be added later without changing the tree backbone.
Poisson/F81 projection uses a stationary weighted sum and one state-wise combination, giving $O(PES)$ work for $E$ edges. HKY uses a cached four-state log transition per edge. Kernels are prepared once per evaluation, rather than per pattern. Tiny-time HKY series avoid cancellation at low transition rates; the integrated kernel uses positive algebra. Extended-range intermediates retain sub-double transitions on the tested Linux platform. Extremely ill-conditioned HKY inputs on platforms without a wider `long double` range can return a recoverable overflow status; no such runtime was tested here.
## Parsimony through the same interface
The common analysis wrapper consumes the same names, patterns, ambiguity and site weights for likelihood and Sankoff parsimony. Equal change costs use $O(PES)$ work; a general directed state-cost matrix uses $O(PES^2)$. Parsimony interprets positive tip observation weights as allowed states, ignoring their magnitude. Branch lengths and likelihood models do not affect parsimony. The existing compact mask-based parsimony API remains available independently.
## Validation and remaining extensions
Tests compare pruning with complete state enumeration, model matrices with independent generator uniformisation and resolvent inversion, and compressed with expanded weights. They cover binary and larger alphabets, polytomies, zero/short/long branches, single root-edge semantics, huge state-likelihood ratios, concurrent worker-local workspaces and failure outputs. The [validation report](validation.md) records build and codec checks.
GTR, numerical matrix backends, site-rate mixtures, upward/outside partials, derivatives, incremental invalidation, proposal rollback buffers and joint shared-edge integration remain separate extensions. GTR would need a cached numerical factorisation or another matrix-exponential implementation; it does not enter the simple models' hot paths. A future optional [libPLL adapter](https://github.com/xflouris/libpll-2) can map stable node IDs and traversal operations into backend buffers without changing the backbone. Select and pin that backend only when its scaling, error, threading and licence requirements can be validated.
