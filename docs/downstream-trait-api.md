# Changes prompted by branchtraits
This update follows the five observations in `branchtraits/docs/curupixa-issues.md`. It changes curupixa on the local `improve-downstream-trait-api` branch. Branchtraits remains an independent downstream consumer; its application and Python interfaces are unchanged.
## 1. Roots, tree size and references
Curupixa uses a rooted **orientation** of a graph: one ordinary node ID identifies the root, whose parent is `CRPX_NODE_NONE`. It has no special implementation tip, three-struct biological nodes, or per-node reference counters. An artificial binary root can represent an unrooted edge for reversible likelihoods; a biological root uses the same storage. A rootedness boolean alone would not express the necessary connectivity or split edge lengths.

The backbone stores parent, first-child and next-sibling indices, totalling 12 bytes per allocated node on the tested ABI. The tree owns contiguous allocations and optionally reserves capacity. Growing can move those allocations, while existing **node IDs** remain stable. Clients hold IDs rather than node-struct pointers. Borrowed array views belong to their workspaces; mutations invalidate derived workspaces through revisions. No node reference count is needed.

`crpx_tree_reroot_edge()` explicitly chooses between reusing the existing artificial binary root (fixed node count) and appending one new root (existing IDs preserved). It preserves taxon labels and pairwise taxon distances. The existing-node `reroot()` remains available. Node labels stay attached to IDs; moving an artificial root also moves its label, so applications must reassess root/support annotations. Root stems follow the new root. Unary root chains are rejected rather than silently deleting nodes. See [tree extensions](tree-extensions.md) for zero edges, end fractions and failure guarantees.
## 2. Binary and polytomous trees
A binary tree already uses the same three indices per node as a polytomous tree; retaining sibling lists adds no per-node storage. Traversals visit each node/edge a bounded number of times. Binary algorithms can explicitly check degree two and request the optional sister array. A second backbone class would duplicate APIs and conversions without reducing these three indices.

Automatic zero-edge resolution is inappropriate as a universal library policy. It preserves a standard fixed-length likelihood when the inserted edge has an identity transition, but unweighted parsimony ignores branch lengths: a binary refinement can change its score. Reconciliation assumptions can also change under a forced resolution. Curupixa therefore keeps genuine polytomies, with explicit binary requirements in algorithms such as PIC and current reconciliation.

For bulk construction, `crpx_tree_builder` keeps child tails outside the tree and provides amortised constant-time ordered appends after preparation. The small existing append API remains available for bounded-degree trees. The builder can be discarded after construction, so all downstream tree users avoid permanent tail arrays.
## 3. Complete reconstruction belongs upstream
The separate [reconstruction API](reconstruction.md) returns full-data likelihood marginals and complete parsimony reconstructions. It shares private transition kernels with likelihood scoring and documents state order, conditioning, root priors, ties and impossible observations. Applications use the mathematical result contract rather than assembling messages from the layout of numerical workspaces.

Score-only likelihood/parsimony retain their existing APIs and skip the outside pass and reconstruction arrays. Marginal node probabilities, one coherent parsimony optimum and globally admissible parsimony states have different meanings and separate accessors. The contract does not freeze an implementation or promise bitwise-identical floating-point results after future algorithm improvements; regression tests enforce the stated calculations within numerical tolerances.

The compact continuous-trait port adds PIC and Brownian ML, with optional ancestral Gaussian marginals; see [continuous traits](continuous-traits.md). These use explicit tip-node/value arrays and linear storage, without a dense tip covariance matrix. Dense PGLS, application-specific rate-search policies and incomplete continuous observations remain downstream work.
## 4. One-off versus repeated likelihoods
`crpx_likelihood_evaluate()` retains the convenient one-off interface and no tree/data pointers between calls. Its workspace reuses numerical capacities, now including kernels and stationary-frequency scratch. No prepared snapshot is constructed implicitly.

For repeated fitting, construct `crpx_likelihood_binding_new(tree,data,&binding)` once, then call `crpx_likelihood_evaluate_prepared(binding,model,&options,workspace,&score)`. The binding owns a tree snapshot and retains the immutable character data through one object-level reference count; observations are shared rather than copied. The original tree/data can be freed. Changing the original tree does not silently alter the binding: construct a new binding to adopt edits. This prevents stale pointer-identity caches, address-reuse mistakes and destruction hazards without global registries.

A binding can be shared read-only by workers with independent numerical workspaces. After warm-up for fixed dimensions and retention mode, rate-only evaluations require no mapping, structural validation, traversal construction or capacity allocations. Models and edge arrays are read afresh on every evaluation, so interleaving models/bindings cannot reuse stale parameters. `crpx_likelihood_workspace_clear()` explicitly releases retained capacity; the storage-size getter includes that capacity and excludes allocator overhead.

Other modules already follow the same principle: no reconciliation, splitset, likelihood, SVD or ancestral buffers attach themselves to a tree. Constructing a tree does not allocate them. `crpx_ancestry_index` is an optional shareable snapshot; `crpx_spr_workspace` reuses capacities and has an explicit clear. Character-analysis score storage grows on request; the Brownian fit defaults to skipping ancestral outputs. Future prepared reconciliation/continuous fitting can use the same explicit lifetime model when benchmarks justify it.
## 5. Representation and validation policy
The broad tree representation remains consistent: finite signed or missing lengths and arbitrary labels are useful during construction, distance fitting and transformations. Each algorithm validates the properties it actually consumes. Name-based likelihood mapping requires unique matching tips; fixed-edge likelihoods reject missing/negative lengths unless valid overrides supply the actual model edges. Parsimony ignores lengths. Brownian/PIC require positive edges and explicit observations. Root stems are excluded from these trait calculations.

The reusable `crpx_tree_validate_policy()` adds opt-in checks for nonempty/unique tip names, complete/nonnegative/positive lengths, binary degree, and inclusion of the root stem. It makes application preflight checks convenient while algorithm entry points retain responsibility for their own requirements. A successful general tree validation alone never promises suitability for every statistical model.
The [complete C/C++ example](../examples/trait_analysis.c) composes prepared likelihood, marginal ASR, parsimony, Brownian fitting and PIC using only public headers.
## Validation and downstream migration
The regression suites include allocation-free repeated likelihood evaluation (100 warmed calls: zero allocations/maps/validations, versus 1,000/100/100 for the ordinary interface in the instrumented static test), snapshot destruction/interleaving/thread tests, exhaustive discrete-state enumeration, independent Gaussian covariance/precision checks, pairwise-distance invariance under root changes, allocator failures and wide-tree construction. Installed headers are checked separately as C17 and C++17. Existing branchtraits regressions run against the updated library without changing branchtraits source.

Branchtraits can progressively replace its edge reconstruction, discrete outside/Sankoff passes and continuous PIC/Brownian core with these public functions. Its rate optimiser can prepare one binding before searching, then request full reconstruction only at the fitted rate. Application-specific table parsing, model selection, result formatting, CLI/Python bindings and PGLS can remain in branchtraits.
