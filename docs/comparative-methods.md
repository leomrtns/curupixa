# Comparisons, ancestral states and comparative methods
These interfaces belong to `curupixa_phylogenetics`, except the mapping adapter in `gene_species_distances.h`. They accept ordinary trees, including gene trees whose copies have distinct tip IDs. A species map is needed only when comparing gene copies with a species tree.
## Shared calculations
Likelihood marginal reconstruction in `reconstruction.h` uses the evaluator in `likelihood.h`, including its prepared transition kernels and downward partials. Joint maximum-probability reconstruction uses the same traversal with maximisation in place of summation. Conditional ancestral sampling uses the summed partials and samples states from the root towards the tips. It therefore returns one coherent assignment; independently sampling each marginal would give a different distribution.
Parsimony scoring in `character_analysis.h`, reconstruction in `reconstruction.h` and the integer scoring interface in `parsimony.h` share the private state-cost transformations in `parsimony_internal.h`. Unit costs and ordered costs have linear state transforms; custom costs retain the quadratic transform. The integer interface preserves its exact integer arithmetic. Brownian fitting and binary-trait dispersion share the Gaussian message calculation in `gaussian_internal.h`.
Create a mutable workspace once for repeated evaluations. Its temporary arrays grow when necessary and are reused. Returned reconstruction, history and regression objects own their result arrays; release them with their matching destructor. Each concurrent calculation needs its own mutable workspace.
## Tree comparisons
`tree_comparison.h` prepares a tree with an explicit array of distinct tip IDs. The same position must identify the same taxon in the other tree's array. The object copies the numerical representation, so changes to the original tree require a new preparation. `crpx_tree_comparison_distance()` returns RF, weighted RF and branch score together. RF counts nontrivial split differences; weighted RF sums absolute edge-length differences; branch score takes their Euclidean norm. The length measures include pendant edges. Sorted split rows are prepared once; repeated comparisons merge them in linear work in the number of stored words, without allocation. Repeated splits from unary vertices have their lengths added; an unrooted binary storage root contributes a single combined edge. Root stems are ignored.
The result reports the number of taxa, the original tip counts and the split counts. You can divide RF by the sum of the two split counts, weighted RF by `length_scale`, or branch score by `branch_scale` when the denominator is positive. The library does not choose a normalisation. Branch score's denominator is the square root of the sum of squared edge lengths from both trees. These denominators describe the chosen comparison coordinates; they do not penalise missing species automatically.
Kendall–Colijn comparison interpolates each pair's root-to-MRCA edge count and root-to-MRCA length, with pendant coordinates, before taking a Euclidean distance. Its `lambda` lies in [0,1]. It cannot be obtained by adding RF and path difference. Path difference compares pairwise tip distances directly, using lengths or edge counts; in unrooted comparisons a degree-two storage root is suppressed. Other unary vertices contribute to edge counts. The one-off wrappers match complete, unique label sets through `tip_correspondence.h`; mismatched sets return an error.
`triplet_distance.h` follows the prepared-index and result conventions of `quartet_distance.h`. Triplets use the supplied root, quartets are unrooted. Both return agreement, disagreement and unresolved counts without picking a treatment of unresolved cases. Exact enumeration costs O(n³) for triplets and O(n⁴) for quartets. Neither routine searches for a species tree.
## Missing species and repeated copies
There is no automatic intersection of tip labels. For example, trees on {A,B,C,D} and {A,B,C,E} fail complete-label matching rather than silently becoming two three-tip trees. If your analysis deliberately compares A,B,C, supply those three tip IDs to the prepared interface; the original tip counts remain available. Splits with no selected tips disappear from the representation and repeated induced splits combine. KC and path coordinates retain distances through the supplied root and unary vertices rather than rerooting or silently contracting the input.
For gene/species comparisons, `crpx_gene_species_comparison_new()` uses every gene copy. Several copies mapped to one species expand that species tip into a zero-length polytomy once during preparation. All scores then call the lower comparison implementation. The object reports `gene_copies`, `represented_species` and `total_species`. An absent gene supplies no observation for its species; it cannot supply a split coordinate. Keep these coverage counts alongside a normalised score when comparing gene families. This explicit copy-expansion distance has different semantics from the ASTRAL-Pro quartet objective.
## Discrete ancestral states and histories
`crpx_likelihood_joint_states()` returns one state per node and pattern. Set `sample=false` for a joint maximum-probability assignment, or `true` for a conditional draw given the observations. A sampled assignment uses the same observation weights and root distribution as the likelihood. Pattern weights describe repeated observations of that pattern; the result contains one assignment per distinct pattern, so call again for independent histories of repeated sites.
`crpx_substitution_model_rates4()` accepts a four-state rate generator and a root distribution. Rows of the generator must sum to zero; off-diagonal rates are nonnegative. It need not be reversible. `crpx_substitution_model_binary_pair()` builds the four states 00,01,10,11 with eight conditional single-bit transition rates. Equal rates for a character across the other character's states give an independent model. Evaluating such models uses the ordinary likelihood interface; fitting parameters or comparing models belongs to your program.
For stochastic histories, first sample ancestral endpoints, then call `crpx_substitution_bridge_sample()` for each branch and pattern. It returns real change times and visited states, omitting virtual self transitions. With likelihood overrides or a collapsed root, use the effective branch parameters from that likelihood rather than the original stored lengths. Uniformisation truncation has an explicit conditional error bound. Choose a tolerance and a virtual-event limit; insufficient capacity or numerical accuracy returns `CRPX_ERROR_CONVERGENCE`, without a history. Rare endpoints can require a larger limit or looser tolerance. This routine conditions on a fixed length; it does not sample a branch length integrated out by another likelihood calculation. See [Hobolth and Stone (2009)](https://doi.org/10.1214/09-AOAS247).
## Continuous traits and regression
The existing `continuous_traits.h` retains its linear-time Brownian fitting, flat-root ancestral reconstruction and independent contrasts. General regression in `gaussian.h` works with any supplied positive-definite covariance. `crpx_phylogenetic_covariance()` constructs one from a tree under Brownian motion or a stationary-root OU process, with optional Pagel lambda and tip error variances. It uses the tree's supplied root and ignores its stem. OU needs positive alpha. Error variances are relative to the diffusion scale subsequently fitted by Gaussian regression.
Prepare the covariance factor once, then use `crpx_gaussian_regression()` for responses or design matrices. Supply an intercept column when wanted. The function fits coefficients, residual variance and their covariance by whitening and Householder QR. Choose ML or REML explicitly. A rank-deficient design is rejected; an exact zero-residual fit has variance zero and an infinite boundary log likelihood. This is a dense calculation: factoring the covariance costs O(n³), and a factor stores O(n²) numbers. The specialised Brownian messages remain preferable when their narrower model is sufficient.
`crpx_phylogenetic_prediction()` prepares conditional ancestral means and marginal variances using the same covariance constructor, then `crpx_gaussian_predict()` evaluates responses with supplied mean vectors without allocation. Brownian prediction here conditions on a fixed root mean; it therefore has different assumptions from the flat-root Brownian fitter. Supply covariance and means at the intended diffusion scale; this predictor does not estimate them.
`crpx_logistic_mixed_fit()` fits a binary response with a supplied Gaussian random-effect covariance, using penalised quasi-likelihood (PQL). A phylogenetic covariance gives a phylogenetic logistic regression. Its covariance scale is supplied rather than estimated. The working regressions call the general Gaussian fitter. Following [Breslow and Clayton (1993)](https://doi.org/10.2307/2290687), PQL is an approximation, and the reported penalised log likelihood is not an integrated marginal likelihood. Non-convergence or separation returns an error. Parameter optimisation and significance testing remain separate operations.
## Bacterial trait association
`crpx_trait_contrasting_pairs()` finds the maximum number of edge-disjoint tip pairs differing in both binary traits. It reports the minimum and maximum number supporting association among all maximum pairings, as used in [Scoary](https://doi.org/10.1186/s13059-016-1108-8). The exact dynamic programme takes O(nodes) time on a rooted binary tree and ignores branch lengths. Supply every leaf; `UINT8_MAX` explicitly excludes an observation. No association model is imposed on the result, and p-values or corrections for multiple testing are separate calculations.
`crpx_trait_binary_dispersion()` computes the raw sum of changes with inverse adjusted-branch-length nodal means, following the `caper::phylo.d` convention. It needs complete binary observations and strictly positive lengths. `crpx_trait_d_statistic()` scales this score with supplied Brownian-threshold and randomly shuffled reference means to obtain [Fritz and Purvis D](https://doi.org/10.1111/j.1523-1739.2010.01455.x). Those reference means are necessary to define D; permutations are not hidden inside the function. Your program can reuse the workspace while shuffling tip values and simulating Brownian-threshold traits, and can reuse the reference means for the same tree and prevalence.
