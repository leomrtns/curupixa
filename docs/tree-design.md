# Tree design
The new tree API consolidates the core operations in biomcmc-lib's `topology_common`, `read_newick_trees`, `topology_distance`, `topology_randomise`, `newick_space`, `topology_space` and `upgma` modules. It uses stable node indices and independent analysis objects. All public constructors and operations return `crpx_status` values, and no operation terminates the calling program or requires an MPI runtime.
## Compact backbone
Each node stores three `uint32_t` indices: parent, first child and next sibling. This occupies 12 bytes on the tested ABI. `CRPX_NODE_NONE` denotes an absent index; a tree can contain at most `UINT32_MAX` nodes. The tree owns one contiguous node allocation. IDs remain stable through reparenting, rerooting, NNI and SPR. Leaves and internal nodes can occur at any ID, and the root can change ID.

Labels and incoming-edge lengths use separate arrays allocated only when requested. Labels add one pointer per allocated node plus their strings; lengths add one double per allocated node. The core has no splits, traversal arrays, update booleans, likelihood vectors, sister pointers, reconciliation maps or reference counters. Each tree has an explicit owner. Cloning copies its data, and collection insertion creates an independent copy.

`crpx_tree_storage_size()` reports the object's owned storage, including capacity and strings, without allocator overhead. `crpx_tree_reserve()` can avoid repeated growth. Incremental insertion appends to a child list, scanning existing siblings; binary construction costs constant work per insertion. Newick parsing keeps a temporary tail for each open node and constructs even large polytomies in linear time.
## Optional analysis objects
`crpx_tree_workspace` allocates only selected arrays. Traversal order costs two indices per node; depth and binary sister lookup each cost one index per node; upstream/downstream update flags share one byte per node. A multifurcation has no unique sister, so the sister array contains `CRPX_NODE_NONE` there. The backbone's sibling list represents all children without resolving polytomies artificially.

Every semantic mutation increments the tree's 64-bit revision. A workspace records its bound tree and revision. Refresh preserves analysis flags when the revision is unchanged; after a change it rebuilds selected arrays and clears flags. This conservative invalidation provides a clear correctness boundary. A future likelihood implementation can add narrower edge-specific invalidation within its own workspace.

A workspace borrows its bound tree. Keep that tree alive until destroying the workspace, rebinding it to another live tree, or calling `crpx_tree_workspace_reset()`. Reset releases the borrowed identity while retaining array capacity. Arrays returned by workspace getters remain owned by the workspace; check `crpx_tree_workspace_is_current()` before using cached data after a mutation.
## Threads, MPI and bindings
Several threads can read the same tree using separate workspaces, and separate MPI ranks own ordinary local objects. The caller synchronises mutation and destruction. No tree operation modifies process-global caches or selects workers implicitly. Random tree/rearrangement functions accept a 64-bit RNG callback and caller-owned state, allowing the application to assign reproducible streams to ranks and threads.

The opaque C types, fixed-width indices, explicit status values and exported destructors provide a straightforward boundary for C++, Python and other bindings. Constructors set their output pointer to `NULL` on failure. Scalar output arguments otherwise remain unchanged on failure. Release Newick strings with `crpx_tree_string_free()`, leaf-order arrays with `crpx_tree_node_ids_free()`, and objects with their corresponding destructor. Borrowed label pointers and collection views become invalid after relevant mutation or destruction.
## Newick and NEXUS
The iterative Newick parser and writer handle deep trees, multifurcations, unary nodes, missing labels, internal labels, finite signed lengths, nested bracket comments, and quoted labels with doubled apostrophes. Every tree requires a terminating semicolon. Underscores remain literal characters. Comments are skipped. Decimal parsing uses a decimal point independently of process locale; writing uses 17 significant digits and normalises the decimal separator. Root stem lengths are retained separately from paths between nodes.

`crpx_tree_space` reads lists incrementally, including compressed input when the optional codec is available. It recognises common NEXUS `TREES`, `TREE`, `UTREE` and `TRANSLATE` statements, skips other blocks, and handles statement boundaries inside quoted names and nested comments. It retains the supplied rooting and translated tip labels. NEXUS tree names, rootedness annotations and posterior-weight annotations are not retained. General NEXUS alignment parsing and a complete NEXUS metadata model remain separate work.

Collections store positive integer sample weights. Appending text, merging and compaction are transactional. Burn-in and thinning select original entry indices before compaction, preserving each selected entry's weight. Frequencies divide entry weights by total weight. Exact compaction merges rooted clades or unrooted splits and retains the first representative's labels and lengths; it performs up to a quadratic number of RF comparisons and suits modest collections. Writing Newick emits each representative once; callers save weights separately. Arbitrary real-valued sample weights, consensus/support summaries, credible-set export, and indexed compaction remain to be implemented.
## Topology and distances
The basic ancestry and LCA queries walk parent chains in `O(height)` time. For repeated LCA/reconciliation calls, an immutable `crpx_ancestry_index` snapshot instead uses `O(nodes log nodes)` storage and `O(log nodes)` queries, without changing the backbone or retaining its tree. Pairwise patristic distance sums the two paths to their LCA; the root stem is excluded. Callers choose whether missing lengths cause an error or use a finite default. Packed leaf-distance matrices require non-negative lengths and use `O(leaves × nodes)` traversal work and packed quadratic output storage.

RF comparison requires unique, matching tip labels. It ignores child ordering, internal labels, edge lengths, trivial splits and repeated unary clades. Rooted comparison counts rooted clades; unrooted comparison canonicalises complementary splits. This calculation allocates separate descendant bitsets in `O(nodes × ceil(leaves/64))` space. Large analyses should budget that optional workspace explicitly.

Subtree exchange, rooted binary NNI and rooted binary SPR preserve node IDs. SPR reuses the pruned node's binary parent. The explicit `graft_fraction` splits the target edge; suppressing the previous parent adds its two retained path lengths. Missing lengths propagate as missing. A graft above the root gives the edge to the old root length zero and transfers the stem to the new root. These rules preserve distances among the retained leaves. Internal support labels remain attached to their node IDs and require reassessment after rearrangement.

Rerooting at an internal node reverses path edges and transfers the root stem. Tip targets and unary previous roots are rejected so that the leaf/taxon set remains unchanged. Rerooting may create a multifurcation at the new root and a unary node at the previous root. The separate `crpx_tree_reroot_edge()` supports fixed-count binary-root reuse or explicit insertion of one new root, with stable IDs and transactional failure; see [tree extensions](tree-extensions.md). Random binary trees coalesce uniformly sampled active pairs, so labelled topologies have unequal probabilities. Random NNI selects eligible internal edges uniformly. Random SPR selects a legal prune node uniformly and then a legal target for that prune; this defines the proposal distribution explicitly for MCMC callers.
## Distance-based construction
UPGMA and single linkage use nearest-neighbour chains with `O(n²)` time and distance storage. NJ and BioNJ use `O(n³)` time and `O(n²)` storage. Inputs remain unchanged, complete finite matrices are required, and tie selection is deterministic. UPGMA weighs clusters by their numbers of tips. NJ/BioNJ callers explicitly choose whether to retain negative estimated limbs or clamp them, redistributing a negative limb's pair distance to its partner where possible.

BioNJ follows the variance reduction in [Gascuel (1997)](https://academic.oup.com/mbe/article-pdf/14/7/685/11165731/1gasc.pdf), using the variance difference $V_{bk}-V_{ak}$ when weighting the $a$ distance by $\lambda$. This differs from the sign used in the local biomcmc-lib implementation. The final two-cluster distance is split equally over an artificial binary root, preserving the pair's path distance. These deliberate changes have focused regression examples in `tests/test_topology.c`.
## Remaining algorithms and likelihood support
The current core covers construction, parsing/writing, traversal, clone/validation, reparenting/rerooting, subtree exchange, rooted binary NNI/SPR, random rearrangements, RF, patristic distances, tree collections, UPGMA, single linkage, NJ and BioNJ. The separate `splitset_distances` module also provides gene/species mapped split RF and assignment-based edge disagreement; its unmatched-edge penalty uses the smaller split-side cardinality. Specialised weighted/short/unrooted move proposals, branch-length fitting and correction routines, and tripartition-based comparisons remain separate algorithms. The optional `spr_distance` module now provides greedy approximate SPR, and `ancestry_index`/`reconciliation_roots` provide binary all-root reconciliation; see [cladistic distances](cladistic-distances.md). Their precise status belongs in the migration inventory.

The likelihood implementation keeps character data, substitution models and partial buffers in separate objects indexed by tree node ID. Their ownership and backend boundary are described in the [likelihood design](likelihood-design.md). This permits a shared read-only backbone with separate partitions, workers and alternative likelihood engines.
