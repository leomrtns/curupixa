# Tree sampling and numerical sequences
General construction and draws live in `sampling.h` in `curupixa_phylogenetics`. Biological priors live in `tree_prior.h` in `curupixa_inference`. Conditional-clade distributions remain in `amalgamation.h` in inference. No sampling function starts threads or chooses a random seed.
## A common random source
All new samplers take a `crpx_uniform_function` callback and its `void *state`. The callback must return a finite value in [0,1). You can pass a Curupixa random stream or your own generator; its state determines reproducibility. Each mutable stream belongs to one concurrent calculation. Invalid draws return an error. A failed operation may have consumed draws, so retrying does not restore the random stream.
`crpx_sample_log_weights()` samples a categorical outcome from log weights without underflowing their common scale. `crpx_sample_permutation()` fills an index permutation for shuffling observations. Both are available without linking inference. Constructors copy labels and return an owned tree through `out`; free it with `crpx_tree_free()`.
## Constructing trees and resolving constraints
`crpx_tree_from_parents()` constructs a tree in linear time from a parent array, optional labels and optional lengths. Input node indices can be in any order. `crpx_tree_from_binary_history()` accepts a merge history and optional node ages; it derives each incoming length from the age difference. Neither constructor assigns a biological model. Returned node IDs need not match input indices.
`crpx_tree_resolve_random()` resolves every multifurcation uniformly over its labelled rooted binary resolutions. It retains each original clade, label and incoming length; new edges have length zero. Each resolution is uniform conditional on the supplied clades. The implementation inserts edges in arrays, then constructs the tree once, avoiding repeated edits to a wide polytomy. Unary vertices survive in the lower interface.
The inference interface `crpx_tree_resolution_sample()` uses this constructor and rejects unary constraints. Its matching `crpx_tree_resolution_log_density()` evaluates the topology probability: a node with d children contributes `-log((2d-3)!!)`. A candidate violating a constraint has log probability minus infinity. Explicit tip arrays identify the correspondence. These probabilities assign no prior to new branch lengths.
## Biological priors
Initialise a `crpx_tree_prior` with its kind and relevant parameters, then call `crpx_tree_prior_sample()` or `crpx_tree_prior_log_density()`. All four kinds return rooted binary trees with contemporary tips. Labels are copied; omitting labels generates numeric names.
| Prior kind | Conditioning and parameters |
| --- | --- |
| `CRPX_TREE_PRIOR_UNIFORM` | Uniform labelled rooted binary topologies (PDA); no branch lengths. |
| `CRPX_TREE_PRIOR_YULE` | Tip count and fixed origin age, positive birth rate, complete extant sampling. |
| `CRPX_TREE_PRIOR_BIRTH_DEATH` | The same conditioning, with nonnegative death rate; critical and subcritical cases are supported. |
| `CRPX_TREE_PRIOR_COALESCENT` | Kingman coalescent with constant pairwise waiting-time scale, for example 2Ne in diploid generations. |
Yule and birth–death return the reconstructed extant tree, excluding extinct lineages and the stem from origin to crown. Their branching ages are sampled conditional on being younger than `origin_age`; this is not a prior conditioned on a fixed crown age. The coalescent chooses a pair uniformly at each merger and draws exponential waits at rate `choose(k,2)/coalescent_scale`. There are no serially sampled tips, changing population sizes, incomplete sampling or fossil lineages in this initial interface. See [Gernhard (2008)](https://doi.org/10.1016/j.jtbi.2008.04.005) and [Kingman (1982)](https://doi.org/10.1016/0304-4149(82)90011-4).
The evaluator returns a density for labelled non-plane trees with respect to ordered branching ages. Child order has no probability factor. Dated inputs must have positive edges and contemporary tips; changing the time unit changes the density. Uniform topology probabilities ignore lengths. No function estimates rates, origin ages or population sizes.
## Sampling from an existing collection
Use `crpx_amalgamation_new()` to prepare a collection of rooted binary trees with a common explicit tip order and optional tree weights. `crpx_amalgamation_sample()` draws a tree and `crpx_amalgamation_log_probability()` evaluates a candidate under that model. Compatible clade splits are sampled conditional on their parent clade, so a sample may be an amalgamation absent from the input collection. This is the existing empirical conditional-clade distribution, not a DTL-conditioned ALE inference procedure.
Independent bipartition frequencies do not generally define a distribution over compatible trees. The conditional-clade representation retains the needed conditioning instead. A maximum-clade-credibility tree is a point summary; drawing from this distribution is a separate operation. Constraints expressed as a multifurcating tree use the resolution interface above.
## Low-discrepancy numbers
`quasi_sequence.h` provides deterministic, seekable Halton, reverse Halton and Sobol sequences in the lower library. No random context is required. `crpx_quasi_sequence_new()` chooses the kind and dimension; `crpx_quasi_sequence_seek()` sets the next point index; `crpx_quasi_sequence_next()` writes one point into a supplied array. The default first point has index 1; seek to 0 to include the origin. Indices run through 2^53-1.
Halton uses distinct prime bases for up to 2048 dimensions; Sobol uses the Bratley–Fox direction numbers for up to eight dimensions. Unsupported dimensions return an error rather than repeating coordinates. These are unscrambled sequences: high-dimensional Halton projections can correlate, and there is no scrambled-QMC error estimate. Sobol support can later be extended with a documented direction-number table. The older `quasi_random.h` API remains available, but new code should use this interface rather than its randomly initialised additive sequence. No quasi-random tree generator is implemented.
