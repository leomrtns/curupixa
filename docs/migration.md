# Migration from biomcmc-lib
This inventory compares the local biomcmc-lib checkout with the new curupixa interfaces. Curupixa changes ownership, types and error handling deliberately. It provides no compatibility aliases. An implemented module means the capabilities described below exist; it does not imply that every legacy helper has a one-to-one replacement. [The symbol inventory](api-migration.csv) lists every parsed function declaration from the legacy public headers and identifies direct name successors separately from interfaces that need manual migration.
## Object and error conventions
New objects use opaque pointers, constructors return `crpx_status`, and constructor outputs become `NULL` on failure. Each object owns its allocations. New code avoids implicit reference counts and process-global errors. Callers can inspect `crpx_status_string()` and choose whether to retry, propagate, log or stop. Pure numerical distribution functions return `NAN` for invalid parameters; IEEE infinity remains a valid mathematical endpoint.
Read-only objects can be shared where the corresponding header permits it. Tree/alignment/hash mutations require exclusive access. Analysis workspaces and random streams belong to one worker at a time. The lazy distance generator serialises cache changes and callback execution explicitly; separate generators permit independent concurrent callbacks.

## Intentional API and behaviour changes
- Trees use `uint32_t` node IDs and three 32-bit connectivity indices per node (parent/first-child/next-sibling). Optional labels, branch lengths, traversal/depth/sister/update arrays have separate allocations. Tree mutations increment a revision; callers refresh each analysis workspace before using its derived arrays.
- New constructors return status plus an output pointer. New objects have explicit `free()` functions. They do not increment the context's reference counter. Borrowed views remain read-only and their lifetime is documented per header.
- Statistical rankings break ties by original index. Histogram mode ties select the smallest value, whereas biomcmc's decreasing sort favoured the larger value. Histograms report arithmetic overflow and accept an empty sample; querying its mode returns `NOT_FOUND`.
- OPTICS counts the query point in `min_points`, includes neighbours at exactly epsilon and supports `min_points=1`. Core/reachability arrays are indexed by original sample, while `order` maps ordering position to sample. Undefined distances remain `INFINITY`; noise/predecessor absence use `SIZE_MAX`.
- Distance components are explicit query arguments. Invalid component IDs return an error instead of wrapping with modulo. Distance callbacks return a status; incomplete/non-finite results are rejected and never cached.
- Poisson CDF log output now computes the log of the upper gamma tail. Legacy code subtracted a log probability from one. Poisson quantile search uses ordinary CDF values consistently and has a bounded representable mean (`lambda <= 2^52`). Extreme log tails such as `P(X=0 | lambda=1000)` remain representable as `-1000`.
- NaN argument checks use `isnan()`. The legacy `x == NaN` comparisons never detected NaNs. Standard C17 `log1p()`, `expm1()` and `tgamma()` replace redundant implementations; the log-gamma implementation avoids shared `signgam` state.
- Gamma and Poisson samplers carry no writable static caches. The gamma sampler uses local Marsaglia–Tsang proposals. Explicit streams reproduce their own sequence; they do not promise biomcmc sequences or mathematically disjoint substreams.
- General split assignment pads unequal split counts with the smaller-side bit count, giving unmatched splits a positive penalty. The separate `spr_distance.h` interface retains the legacy zero dummy penalty inside its heuristic and labels that convention explicitly. It corrects the skipped single-pair assignment; estimates can differ under equal-cost ties. See [cladistic distances](cladistic-distances.md).
- The dense SVD backend reports `CONVERGENCE` when the sweep budget is exhausted, and `OVERFLOW` for unrepresentable singular values. It uses local workspaces and sorted thin factors. Its O(rows*columns) materialisation makes it a different scalability choice from legacy sparse LAS2.
- Compression availability is checked before creating output. Unsupported codecs return `UNSUPPORTED`; raw I/O remains available without optional dependencies.
## Likelihood implementation
The [common character-analysis guide](character-analysis.md) describes fixed-edge and sitewise exponential likelihoods and matching parsimony calls. The [reference audit](likelihood-reference-audit.md) distinguishes the implemented per-site prior from an alignment-wide shared-edge marginal. The [likelihood design](likelihood-design.md) documents current complexity and future backend boundaries. Neither a GTR engine nor libPLL is required for the closed-form models.

## Guenomu and genefam-dist algorithms
The [cladistic/reconciliation guide](cladistic-distances.md) records the adapted dSPR heuristic, hdist conventions, explicit taxon mapping and binary all-root reconciliation. Each optimum has its own candidate index; loss scope is an explicit argument. LCA snapshots use binary lifting instead of attaching a quadratic MRCA cache to the species tree. These are semantic successors with redesigned ownership, rather than legacy structure/function aliases. Header dependencies and loading behaviour are described in the [footprint guide](library-footprint.md).

## Trait-analysis additions
The [downstream trait API response](downstream-trait-api.md) covers stable-ID root insertion, optional tail-aware construction, full marginal likelihood ASR and Sankoff assignments/global state sets, explicit prepared likelihood snapshots and operation-specific validation. `continuous_traits.h` adds linear-memory PIC and Brownian ML, with ancestral marginals allocated only on request. These additions leave the score-only interfaces and compact node layout intact.
