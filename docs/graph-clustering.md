# Graphs, assignment and clustering
These interfaces belong to `curupixa_phylogenetics`. Include the header for the calculation you need and link that library; `phylogenetics.h` collects them all. They accept graph edges, byte sequences or supplied distances, so they can also be used outside phylogenetics. No routine starts worker threads or changes a tree.
| Header | Public calculation | Shared implementation |
| --- | --- | --- |
| `assignment.h` | `crpx_assignment_jv`, with an optional retained workspace | Modified Jonker–Volgenant shortest augmenting paths. The existing Hungarian `crpx_assignment_solve` in `lowlevel_algorithms.h` remains available. |
| `graph.h` | `crpx_dijkstra`, `crpx_prim`, `crpx_kruskal`, `crpx_prim_dense` | CSR graph storage; private heap shared with OPTICS; union–find shared with the density hierarchy. |
| `clustering_goptics.h` | OPTICS ordering and DBSCAN extraction, from a distance generator or radius-query callback | One ordering kernel for both interfaces, with an indexed minimum heap and the existing selection primitive. |
| `hdbscan.h` | HDBSCAN* labels, membership strengths, selected-cluster stabilities and condensed hierarchy | Core-distance selection, dense Prim on mutual reachability, hierarchy condensation and excess-of-mass/leaf selection. An external MST can enter at the condensation step. |
| `kmedoids.h` | PAM BUILD and FastPAM1 optimisation | The distance generator and cached nearest/second-nearest medoid distances. No coordinate representation is required. |
All constructors initialise their output pointer to `NULL`; release successful results with the corresponding `free` function. Workspaces and iterators belong to one calculation at a time. Graphs and completed results can be read concurrently. The distance generator serialises its callback; different generators can run concurrently when their callback data permits it. An uncached generator now retains one component buffer and performs no allocation for each distance query.
## Assignment
`crpx_assignment_jv` has the same matrix parameters and output convention as `crpx_assignment_solve`: a finite non-negative row-major cost matrix with rows no greater than columns, one selected column per row, and the minimum total. Neither function modifies the matrix. Equal-cost optima can produce different assignments. Both take worst-case $O(r^2c)$ time and $O(r+c)$ scratch space.
For repeated calculations, create a `crpx_assignment_workspace` with the largest required dimensions, then call `crpx_assignment_jv_with_workspace`. Each call resets the matching and potentials, so it can accept unrelated matrices and smaller dimensions without reallocating. The workspace is not a warm-start approximation; the returned matching is solved for the new costs. Invalid input or an unrepresentable total leaves the supplied outputs unchanged.
The implementation adapts PM Larsen's BSD-licensed SciPy `rectangular_lsap.cpp`, commit `2dd345a7824adb2af902d939a7ba9385c4de4351`, to C17 and reusable storage. It follows [Crouse (2016)](https://doi.org/10.1109/TAES.2016.140952). The retained notice is `LICENSES/Assignment-SciPy-BSD-3-Clause.txt`.
## Shortest paths and spanning forests
Construct a graph with `crpx_graph_new` from edges whose endpoints are integer IDs. The constructor copies the edges into compressed adjacency arrays. Directed and undirected graphs, parallel edges, loops and zero weights are accepted. Weights are finite; Dijkstra additionally requires non-negative values.
Dijkstra minimises the distance from one source to every reachable vertex. `distances` and `predecessors` are supplied by your program; unreachable distances are `INFINITY`, and missing predecessors are `SIZE_MAX`. A predecessor chain gives the path. The source has no predecessor. Negative weights return an error, including in disconnected components.
Prim and Kruskal minimise the **total edge weight** of an undirected spanning forest. Negative weights are valid here. A connected graph produces a tree; a disconnected graph produces one tree per component. The returned `crpx_spanning_forest` exposes its edges, component count and total weight. Graph storage does not change during either calculation. Heap-based Prim takes $O((V+E)\log V)$ time; Kruskal sorts edges in $O(E\log E)$ time.
`crpx_prim_dense` accepts a symmetric pair-weight callback, without constructing graph adjacency or a distance matrix. It takes $O(V^2)$ time and $O(V)$ extra memory. Return `INFINITY` for an absent edge; finite negative weights are accepted. This interface also builds HDBSCAN's mutual-reachability MST. If your distances are expensive, retain them in the existing distance generator or compute/cache suitable graph edges upstream.
The mathematical references are [Dijkstra (1959)](https://doi.org/10.1007/BF01386390), [Prim (1957)](https://doi.org/10.1002/j.1538-7305.1957.tb01515.x) and [Kruskal (1956)](https://doi.org/10.1090/S0002-9939-1956-0078686-7). These graph kernels were written for Curupixa; no third-party implementation was imported.
## OPTICS
The original `crpx_optics_run` still accepts a distance generator. It now uses a heap for reachability updates and reuses distance-query storage. Its full scan makes $O(n^2)$ distance queries and uses $O(n)$ scratch space. Heap updates add $O(M\log n)$ work, where $M$ is the number of reported neighbourhood links; this does not remove the quadratic distance cost of an unindexed search.
`crpx_optics_run_neighbours` accepts a radius-query callback instead. Supply all other samples within the inclusive radius, once each, as sample IDs and distances. The query point itself is implicit and counts towards `min_points`. This permits a downstream k-d tree, metric index or precomputed neighbourhood graph to avoid the full scan. The callback need not sort its output. Equal reachability values use sample ID, so callback output order does not change the ordering. Both entry points return the same result type and use the same DBSCAN extraction function.
The existing leading-border-point correction remains: extraction can attach a point that appeared before its first adjacent core point. Neighbour-query failure propagates to the calling program. The reference is [Ankerst et al. (1999)](https://doi.org/10.1145/304182.304187).
## HDBSCAN*
`crpx_hdbscan_run` takes the density parameter `min_points`, a minimum cluster size, the selection method and `allow_single_cluster`. As in OPTICS, `min_points` **includes the query itself**. Core distance is the corresponding neighbour distance. Mutual reachability between two samples is the maximum of their ordinary distance and both core distances. The implementation obtains an MST of those weights using `crpx_prim_dense`, then constructs and condenses its hierarchy. Generic distance input needs $O(n^2)$ queries and $O(n)$ extra memory; optional distance-generator caching has a separate quadratic storage cost.
`crpx_hdbscan_from_mst` accepts a connected mutual-reachability MST computed elsewhere. This permits external nearest-neighbour indexes or a previously stored MST to be reused. The function checks the tree's structure and weights; the supplied MST and core-distance convention must describe the intended calculation. An ordinary distance MST generally gives a different hierarchy.
Excess-of-mass selection (`CRPX_HDBSCAN_EOM`) chooses non-overlapping clusters that maximise their summed stability. Leaf selection (`CRPX_HDBSCAN_LEAF`) chooses non-root leaves of the condensed hierarchy. EOM can select the root only when `allow_single_cluster` is true; then points that left before its last density level remain noise. Labels index the returned `selected_clusters` and `stabilities` arrays. Noise is `SIZE_MAX` with membership zero. Membership strength is survival density relative to the selected cluster's maximum density, capped at one; it is not a calibrated posterior probability.
Condensed edges identify parent cluster, child cluster or point, child size and density $\lambda=1/d$. Point IDs use `0..n-1`; cluster IDs start at `n`. Zero distances can produce infinite densities and stabilities. Membership strengths remain finite, including for identical observations. Internal density arithmetic uses `long double`; returned density/stability doubles may overflow to infinity when the corresponding mathematical value exceeds their range.
**Tied merges occur simultaneously.** All equal-weight edges are processed as one split before the minimum-size rule is applied. A point leaving at that split belongs to the parent history, rather than being attached arbitrarily to one child. This avoids zero-lifetime clusters and makes results independent of edge ordering at ties. Implementations that process tied merges one at a time can return different boundary labels or membership normalisations, even on otherwise continuous data because mutual-reachability weights repeat core distances. Curupixa does not promise identical outputs to every package's tie convention.
The mathematical reference is [Campello et al. (2015)](https://doi.org/10.1145/2733381). The implementation was written from the hierarchy and stability definitions; it imports no HDBSCAN package source.
## K-medoids
`crpx_kmedoids_run` accepts a distance generator, $k$, optional initial medoid sample IDs and a maximum number of accepted swaps. With no initial IDs it uses deterministic PAM BUILD. Each cluster representative is an observed sample, and the objective is the sum of distances to the nearest representative. The result exposes medoids, labels, distances, objective cost, swap count and convergence flag. Representatives label themselves, including when observations coincide.
FastPAM1 evaluates a candidate against every possible removal using shared sums and each point's nearest two distances. Each swap search takes $O(n^2+nk)$ work and $O(n+k)$ scratch memory; deterministic BUILD takes $O(kn^2)$ work. Accepted swaps decrease the objective. Changes below a scale-dependent bound for summation round-off are ignored. A result with `converged=false` is usable, but the supplied swap limit was reached before a local optimum was established. A limit of zero evaluates the initial medoids. Multiple starts or a different search strategy can call this function with different initial IDs; no stochastic search is imposed by the library.
This is an implementation of [Schubert and Rousseeuw's FastPAM1 equations (2021)](https://doi.org/10.1016/j.is.2021.101804), written for Curupixa. It shares no code with GPL R clustering packages.
## Validation and measured costs
The C tests compare rectangular assignment with exhaustive enumeration and the retained Hungarian solver, Dijkstra with Floyd–Warshall on directed and undirected random graphs, and FastPAM1 with brute-force PAM swap searches. They also exercise negative MST weights, zero edges, disconnected graphs, callback failures, duplicate observations, indexed/full-scan OPTICS equivalence and a 10,000-point hierarchy without recursion.
The optional `tests/check_graph_clustering_reference.py` needs NumPy, SciPy and scikit-learn in its Python environment. It checks 500 assignments against SciPy and 480 HDBSCAN configurations against a separate calculation that repeatedly cuts a SciPy MST and finds connected components. In the recorded run all 480 agreed with the simultaneous-cut calculation; 401 also agreed exactly with scikit-learn's labels and membership strengths. Differences occurred at tied splits. All tested configurations without tied core-distance merges agreed, including both selection methods. The reference packages used were SciPy 1.18.1 and scikit-learn 1.9.1.
Local release-build timings, after warm-up, put 256-by-256 integer-cost assignments at about 4.5–4.6 ms for the retained Hungarian solver and 2.7 ms for JV with a retained workspace. On 2,500 evenly spaced one-dimensional points, radius two and `min_points=3`, the previous uncached OPTICS implementation took about 172–179 ms and the revised full scan 88–91 ms. A direct indexed radius callback took about 0.14–0.29 ms. These timings describe those inputs and this machine; index construction and other distance functions can change the comparison.
