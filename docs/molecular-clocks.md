# Molecular clocks and particle weights
Molecular clocks supply substitution lengths to the existing likelihood evaluator. They add no fields to a tree and require no allocation until requested. `clock.h` and `particle_weights.h` belong to general phylogenetics; the probability models in `molecular_clock.h` belong to inference. The downstream [phyloSMC program](https://github.com/leomrtns/phyloSMC) combines these primitives into annealed and online inference.
## Dates, rates and likelihood
`crpx_clock_lengths()` accepts node ages increasing into the past, plus either absolute branch rates or a single positive rate. It returns `(parent_age-child_age)*rate` for every incoming edge. Supply the resulting array through `crpx_likelihood_options.edge_values`; the tree can keep its time lengths. The root stem has no substitution length. Arrays use node IDs, and the conversion supports multifurcations, unary nodes and dated tips. Zero durations give zero substitution lengths. No rate is estimated or rescaled implicitly.
`crpx_tree_ages()` reconstructs ages from time lengths and supplied leaf ages. Omit leaf ages for contemporary tips at zero. Every path to the tips must imply a consistent age for an internal node, within the supplied tolerance. Supply a traversal workspace once and reuse it. The function resets its borrowed tree identity after each call, allowing the input tree to be freed safely.
Likelihood uses substitution lengths, whereas a dated tree prior uses time lengths. Retain the distinction when preparing data or proposals. A rate has substitutions/site/time units; changing the time unit requires a corresponding change in rates and prior parameters. Rate–time confounding is a property of the model, and the converter does not resolve it. A downstream analysis must provide suitable scale information or assumptions.
## Rate models
Initialise a `crpx_clock_model` with its kind, arithmetic mean rate and relevant dispersion, then call `crpx_clock_sample()` or `crpx_clock_log_density()`. Both functions use the same conditional distributions. The root array entry equals the supplied mean rate and has no density factor. They borrow no arrays or input pointers after returning; separate concurrent evaluations need separate mutable workspaces and random streams.
| Kind | Definition |
| --- | --- |
| `CRPX_CLOCK_STRICT` | Every branch rate equals the supplied mean. Sampling is deterministic; scoring returns zero on this point mass and minus infinity elsewhere. |
| `CRPX_CLOCK_LOGNORMAL` | Independent lognormal branch rates with supplied arithmetic mean m and log standard deviation s: log rate has mean `log(m)-s²/2`. |
| `CRPX_CLOCK_EXPONENTIAL` | Independent exponential branch rates with mean m. Dispersion is unused. |
| `CRPX_CLOCK_AUTOCORRELATED` | Conditional lognormal rates between branch midpoints, with conditional arithmetic mean equal to the parent's rate. |
For the autocorrelated model, conditional log variance is `dispersion²*(child_duration+parent_duration)/2`. Root children use the fixed mean rate at the root and half their own duration. Thus dispersion has inverse square-root time units; independent lognormal dispersion is dimensionless. Zero-time conditional transitions are point masses. Positive dispersion is required for both lognormal kinds; use the strict kind for a deterministic rate. The model uses constant rates along branches when calculating sequence lengths. It does not integrate a continuous geometric Brownian trajectory within a branch. See [Drummond et al. (2006)](https://doi.org/10.1371/journal.pbio.0040088) for independent relaxed clocks and [Thorne et al. (1998)](https://doi.org/10.1093/oxfordjournals.molbev.a025892) for autocorrelation in molecular dating; the header specifies the midpoint convention used here.
The returned log density is with respect to branch rates, conditional on dates and model parameters. It excludes the age prior, calibrations, hyperparameter priors and any Jacobian introduced by a downstream parameter transformation. In particular, proposing a rate in log coordinates still requires the appropriate proposal-density ratio. Tree-prior sampling and density evaluation remain in `tree_prior.h`.
## Numerical SMC primitives
`crpx_particle_normalise()` converts log importance weights to ordinary probabilities, returning the log normaliser and effective sample size. It supports zero weights represented by minus infinity. All-zero mass returns `CRPX_ERROR_NOT_FOUND`. `crpx_particle_temperature()` chooses a likelihood-power increment by conditional ESS using bisection, with explicit current weights and finite scores. Neither function owns a particle population or decides when to resample.
`crpx_particle_resample()` returns ancestor indices under systematic or stratified resampling. Your program owns the particle states and decides how to copy them. The functions allocate no memory. Random callbacks follow the existing checked `crpx_uniform_function` convention.
`crpx_tree_insert_tip()` inserts a tip into a supplied edge or above the root, retaining old path lengths when splitting an edge. It is a deterministic operation, and therefore defines no proposal distribution. The input tree is unchanged, but returned node IDs can differ. Root stem metadata is omitted. Online algorithms must include the chosen edge, new lengths and split-coordinate Jacobian in their proposal probability; phyloSMC provides one such implementation.
