# Runtime, random streams and sequence indexes
## Ownership and parallel execution
New data containers return `crpx_status`, hold their own storage and expose opaque types. Their constructors initialise the output pointer to `NULL` and publish an object only after successful allocation. A mutable object belongs to one worker at a time; callers may share immutable objects and give each worker a separate iterator or analysis workspace. Curupixa does not initialise MPI or select a process/thread scheduling policy.
The legacy `crpx_global_t` remains available for the existing random, logging and combinatorial interfaces. Its RNG and logger use C11 atomics internally, including callers from POSIX threads and nested OpenMP regions. Context construction returns `NULL` on failure. Each context holds one serialised RNG state rather than allocating a vector sized from OpenMP's current thread count. Holding a shared context reference keeps it alive; use `crpx_global_retain()` before publishing that reference and `crpx_global_finalise()` once for each owner. Direct context field access requires caller synchronisation. Logger calls record an error even when its message is filtered out.
The context layout and corrected RNG algorithms differ from the old experimental version. Recompile downstream code against this version. Corrected seeding and algorithm defects also change historical random sequences.
## Reproducible worker and MPI streams
`crpx_rng_stream` is an allocation-free caller-owned SplitMix64 stream. Initialise it with a user seed and a stable worker/rank identifier. Seed zero is deterministic in this API. The legacy `crpx_global_init(0, ...)` instead requests OS entropy. Distinct stream identifiers yield distinct starting states for a fixed seed, while the same seed/identifier reproduces the same sequence. These initialisations do not guarantee non-overlapping substreams.
```c
crpx_rng_stream stream;
uint64_t stream_id = ((uint64_t)rank << 32) | (uint32_t)worker;
crpx_rng_stream_init(&stream, user_seed, stream_id);
uint64_t choice;
crpx_status status = crpx_rng_stream_range(&stream, number_of_choices, &choice);
if (status != CRPX_OK) return status;
double uniform = crpx_rng_stream_double(&stream); /* [0, 1) */
```
The example reserves 32 bits each for rank and worker. Assign identifiers independently of execution order. Shared-context RNG draws are safe, but their assignment to workers depends on scheduling. Separate worker-owned streams avoid that scheduling dependency and shared RNG lock contention.
## Hashing and indexes
`kmerhash.h` provides an exact two-bit canonical DNA iterator for `k=1..32`. Each step returns the original sequence position, forward and reverse-complement encodings, the canonical encoding, orientation and a seeded final hash. A/C/G/T/U are case-insensitive; other bytes break the contiguous window. The iterator borrows the input sequence and never joins bases across an ambiguous character or gap. Spaced seeds, longer k-mers and the legacy one-bit/four-bit encodings remain future work.
`rolling_hash.h` provides a seeded polynomial hash for arbitrary byte windows, including embedded zero bytes. It computes the first window in linear time and updates successive windows in constant time. It borrows the input; keep the bytes unchanged until reset or destruction. Hashes are non-cryptographic.
`hll.h` provides classic HyperLogLog with 64-bit hashes, precision 4..18, reset/clone, checked merging and a stable little-endian serialisation. Build separate sketches per worker/rank and merge them after synchronisation. Merge requires identical precision and seed. `crpx_hll_add_hash()` accepts an already uniform hash; all participating callers must use the same hashing convention. Estimates follow the [original HyperLogLog estimator](https://algo.inria.fr/flajolet/Publications/FlFuGaMe07.pdf), including linear counting for small cardinalities; theoretical relative standard error is approximately $1.04/\sqrt{m}$ for $m$ registers. HLL++ bias corrections and sparse representations remain future work.
`suffix_tree.h` provides an immutable suffix-array/LCP index through `crpx_suffix_index_*`. It copies arbitrary input bytes and supports exact substring ranges, suffix coordinates, longest common prefixes and longest repeated substrings. Construction uses linear memory and $O(n\log^2 n)$ time; matching returns positions in suffix order. This API replaces the older pointer-heavy suffix-tree representation. General tree-node enumeration and specialised suffix-tree algorithms remain future work.
## GFF3 annotations and compressed input
`gff3_format.h` owns parsed annotations and returns read-only feature views. It converts GFF3 one-based closed coordinates to zero-based half-open intervals, so a feature written as `1..10` has `start=0,end=10`. All overlap queries use that convention and include nested and overlapping features. Comma-separated attribute values remain distinct from percent-escaped commas within one value. The writer preserves comments and unknown directives in the annotation section; embedded FASTA is normalised by the alignment parser. External FASTA attachment copies data and links the exact first identifier in each description to the decoded sequence identifier. Duplicate first identifiers fail without replacing the existing sequences.
The parser follows the [Sequence Ontology GFF3 format specification](https://github.com/The-Sequence-Ontology/Specifications/blob/master/gff3.md) for field syntax, escaping, strands, phases and sequence regions. It requires `##gff-version 3` and a phase for `CDS`. Ontology validation, Parent-graph validation and specialised alignment interpretation of `Target`/`Gap` remain future work; their attribute values are retained. `%00` returns `UNSUPPORTED` because public strings are NUL-terminated. Features crossing a circular origin may extend beyond a declared sequence region, as permitted by GFF3. Overlap queries currently scan the feature array and do not assume non-overlapping intervals.
`file_compression.h` gives each worker an independent file handle. Raw files need no extra dependency; gzip, bzip2 and XZ support are optional build features. Compressed readers detect the format from magic bytes, process concatenated members, and report errors for truncation or trailing garbage when read to EOF. XZ permits standard stream padding. Opening an explicit compressed format requires valid compressed headers. Early close does not validate unread compressed input; callers requiring whole-file integrity should read to EOF and check every read and close status. A failed backend remains failed, so a later close cannot hide an earlier read/write error.
