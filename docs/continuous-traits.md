# Continuous traits: Brownian reconstruction and PIC
`continuous_traits.h` adapts the compact Gaussian-pruning and independent-contrast core from branchtraits into a general curupixa module. It adds no node fields, external dependencies or dense tip-covariance matrix. Each call uses linear work/storage, and its opaque result owns all returned arrays independently of the tree. The application can release its tree after the call. Concurrent calls can read the same immutable tree; mutation and destruction remain caller-synchronised.
## Explicit observations and edge requirements
Pass parallel arrays `tip_nodes[i]` and `values[i]`, with one finite observation for every tip. Node IDs identify the mapping, so names, duplicate names and internal labels are irrelevant. The functions validate count, uniqueness and tip identity. Missing/nonfinite observations are rejected. Each non-root edge must have a finite, strictly positive length; root stem values are ignored. Zero or negative lengths return an error because the current contrast/Gaussian recursions require positive evolutionary variances. A future treatment of exact equality constraints would require an explicit model extension.
## Brownian likelihood and reconstruction
`crpx_brownian_fit()` estimates the root mean and diffusion variance by maximum likelihood, with variance estimate $\hat\sigma^2=\mathrm{SSE}/n$ for $n$ tips. This is the Gaussian tip density at fitted parameters. The diffusion parameter has trait-squared per branch-length units. Constant data have a boundary estimate with no finite optimum density and return `CRPX_ERROR_INVALID_ARGUMENT`.

Default options perform only the downward fit. They allocate no result arrays for ancestors and skip the outside-subtree pass. Set `crpx_brownian_options.reconstruct=true` to obtain each node's marginal mean and variance, conditional on all tip observations under a flat prior on the root state and plug-in fitted diffusion variance. The reconstruction integrates the root state rather than fixing it at the fitted mean, so it includes root-state uncertainty; diffusion-rate and tree uncertainty remain excluded. These variances have trait-squared units. The tip means equal the observations and tip variances are zero. Polytomies and unary vertices are supported. Gaussian prefix/suffix products exclude each child's contribution in constant work per edge, without subtracting almost equal precisions.

The result getters return owned read-only views indexed by the original tree's node IDs. Score-only results return `NULL` and count zero for the ancestral arrays. The summary scalars remain available in both modes; the result does not borrow tree/workspace identities.
## Independent contrasts
`crpx_pic_calculate()` calculates standardised phylogenetically independent contrasts on a strictly bifurcating rooted tree. Nonbinary trees return `CRPX_ERROR_UNSUPPORTED`. Constant data are valid and produce zero contrasts. Each contrast uses first-child minus second-child sign, divided by the square root of their adjusted branch-length sum. Signs can therefore change when child order changes; squared contrasts and their interpretation remain unchanged. Output arrays give the internal node, standardised contrast and pre-standardisation variance in postorder. Non-ultrametric trees are supported.
## Validation and deferred models
Tests independently construct the dense Brownian tip covariance on small trees to verify ML means, rates and likelihoods. A separate conditional Gaussian precision matrix verifies every ancestral mean and variance. Binary examples also compare the sum of squared contrasts with the independent covariance-based residual sum of squares. Tests cover unary vertices, polytomies, unequal tip depths, negative root stems, exact contrast examples, score-only allocation policy, invalid mappings, missing data, zero/missing lengths and result ownership after tree destruction.

Dense PGLS, automatic root placement, measurement error, missing-observation models, multivariate diffusion and fitted model transforms remain separate future work. Branchtraits' dense PGLS solver has cubic tip-count time and quadratic memory; migrating that implementation would conflict with the immediate small/fast core goal. It can instead become an explicitly selected backend after its statistical and numerical contract is specified. Branchtraits can replace its existing Brownian/PIC implementations with these calls while retaining its own data loading, naming, rate-reporting and application policies.
