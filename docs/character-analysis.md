# Discrete characters, likelihood and parsimony
`crpx_character_data` gives likelihood and parsimony one immutable input representation. `crpx_character_analysis` owns reusable numerical workspaces and exposes both calculations with the same tree/data arguments and status convention. The [binary example](../examples/discrete_characters.c) constructs a three-taxon data set, evaluates fixed-length likelihood and calculates unordered parsimony with the same objects.
## Constructing data
Names are unique, nonempty taxon names. Tree leaves must match these names exactly, independently of their node IDs or ordering. Constructors copy input arrays and return an opaque owned object; constructor failure sets its output pointer to `NULL`. The tree, data, model and analysis workspace have separate destructors.
Use `crpx_character_data_from_states()` for arbitrary discrete state indices `0..states-1`, with `SIZE_MAX` for an unknown observation. `from_binary()` accepts `0`, `1` and `UINT8_MAX` for unknown. `from_masks()` accepts nonzero sets of allowed states for up to 64 states; the low bit denotes state zero. `from_tip_likelihoods()` accepts nonnegative finite observation weights for any positive state count, including counts above 64. At least one state per taxon/site must have positive weight. `from_alignment_dna()` converts an existing DNA alignment and preserves IUPAC ambiguities.
State and mask inputs have site-major layout `[site][taxon]`. General observation-weight inputs have layout `[site][taxon][state]`. An unknown observation has weight one for every state. These are likelihood weights for the observation conditional on the true state; normalising an ambiguous observation to sum to one changes its likelihood by a constant and is unnecessary.
Optional compaction combines exactly equal columns and sums their nonnegative integer site weights with overflow checks. Pattern values use `[pattern][taxon][state]` layout. The data object exposes borrowed read-only pattern values, pattern weights and original-site-to-pattern indices. Their lifetimes end when the object is freed. Zero site weights are permitted. Empty alignments with zero sites evaluate to zero total log likelihood or parsimony score after taxon/model validation.
Dense pattern storage costs $O(PNS)$ doubles for $P$ patterns, $N$ taxa and $S$ states. Construction can temporarily reserve space for every input column before shrinking to the distinct patterns. Large alphabets therefore have an explicit data-memory cost; the tree backbone remains independent of the alphabet.
## One analysis workspace per worker
Create an unbound `crpx_character_analysis`, then call `crpx_character_analysis_likelihood()` or `crpx_character_analysis_parsimony()`. Each call validates the taxon mapping. No input ownership transfers to the workspace, and it retains no borrowed input references between calls. Immutable data/models and a read-only tree can be shared across workers with separate analysis workspaces. Mutating or freeing a shared tree requires application-level synchronisation.
The likelihood method accepts an immutable substitution model and branch options. NULL branch options use each non-root node's stored incoming-edge length. The numerical likelihood workspace is available through a borrowed accessor for per-pattern log likelihoods and scaled partial-vector inspection. Refreshing an evaluation invalidates previous borrowed numerical views.
The branch options also support analytically averaging individual transition matrices under exponential length priors. This is a sitewise model: it averages each transition independently for each site. It differs from integrating the complete alignment likelihood with one random branch length shared across all sites. A sitewise calculation has the form
$$
\sum_p w_p\log\left[\sum_{\text{ancestral states}}\pi_{\text{root}}\prod_e\mathbb E_{t_e}\{P_e(t_e)\}\right].
$$
The model/likelihood headers specify parameter units, root treatment and explicit per-edge options. A caller should choose that statistical interpretation deliberately before using the exponential mode as a score for a tree without fixed lengths.
`crpx_likelihood_options_init()` sets fixed-length defaults. Set `branch_mode=CRPX_BRANCH_SITEWISE_EXPONENTIAL` and `mean_branch_length` to average each supplied edge with the same exponential mean. Alternatively, `edge_values` gives one nonnegative value per node: fixed lengths or exponential means according to the selected mode. The root entry is ignored.
An artificial binary root splits one unrooted edge into two supplied edges. For fixed lengths their sum determines the transition along that edge. With independent exponential priors, those two edge lengths instead sum to a different prior from one exponential length. Set `collapse_binary_root=true` and provide `root_edge_value` to treat the two root-child edges as one kernel with the supplied length or prior mean; this requires exactly two root children. Their original two edge parameters are then ignored. Other degree-two vertices remain explicit edges. The example shows both prior choices so the score's statistical meaning is visible in downstream code.
Likelihood work uses logs and per-node scales. `crpx_likelihood_workspace_log_partial()` provides normalised log partials and a log scale; adding that scale recovers their unnormalised logs. The ordinary partial accessor exponentiates into a borrowed scratch vector and can underflow very small state contributions. Workspaces retain their largest allocated capacity for reuse; free and recreate a workspace to release earlier large allocations. Retaining every partial costs $O(PVS)$ doubles for $V$ nodes; `retain_partials=false` reuses $O(VS)$ working storage and disables partial queries, while retaining per-pattern log likelihoods.
## Parsimony models
NULL change costs with a zero cost count selects unordered, equal-cost Sankoff parsimony. A change costs one and an unchanged state costs zero. Hard polytomies and unary nodes are handled directly. The implementation takes $O(EPS)$ work for $E$ edges and $P$ patterns, with $S$ states; it uses the minimum child cost to avoid an extra state loop.
For general Sankoff costs, provide a row-major matrix `cost[parent_state][child_state]` containing finite nonnegative entries and a zero diagonal. Directed/asymmetric costs are supported, so changing the root can change the result. This mode takes $O(EPS^2)$ work. Parsimony treats each positive observation weight as an allowed state and ignores its magnitude; use an explicit cost matrix to represent unequal change costs.
The returned total uses pattern weights; the per-pattern score accessor returns unweighted scores. Unit-cost totals are checked exactly up to $2^{53}$, the range of consecutive integers in `double`; larger totals return `CRPX_ERROR_OVERFLOW`. General floating-point costs use checked floating-point accumulation. Scalar outputs remain unchanged on failure, and a failed parsimony call clears the pattern-score view.
`parsimony.h` remains available for the existing compact 64-state-mask API. The new wrapper shares the arbitrary-state data representation with likelihood and provides the additional cost-matrix interface.
## Example and concurrency validation
The example includes the public `curupixa.h` umbrella. It was compiled with strict C17 warnings and run from a separate consumer of a freshly installed package through the exported target:
```cmake
find_package(curupixa CONFIG REQUIRED)
add_executable(discrete_example /path/to/curupixa/examples/discrete_characters.c)
target_link_libraries(discrete_example PRIVATE curupixa::curupixa)
```
The example reports fixed-length log likelihood `-5.39209264`, sitewise exponential log likelihood `-6.49189976`, collapsed-root sitewise log likelihood `-7.68647685` and parsimony `3`. Its three likelihood scores use different explicit branch assumptions.
The character-analysis regression suite also runs four POSIX workers against the same read-only tree, data and model, with one analysis workspace per worker. Each worker repeats fixed-length likelihood, streaming sitewise likelihood and parsimony 100 times and compares the results with independently calculated serial scores. This passes under AddressSanitizer and UndefinedBehaviourSanitizer; those tools check memory/undefined behaviour, rather than proving the absence of every possible thread race.
